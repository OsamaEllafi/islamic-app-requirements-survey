# استبيان تحديد متطلبات التطبيق الإسلامي

تطبيق ويب تفاعلي لجمع متطلبات تطبيق إسلامي شامل. يجيب العميل على الأسئلة عبر واجهة عربية
بالكامل (RTL)، ثم يُنشئ التطبيق ملف Markdown ويُنزّله تلقائيًا على جهاز العميل — دون أي خادم
أو قاعدة بيانات.

**Interactive requirements-gathering survey for an Islamic mobile app.** Fully client-side:
React + TypeScript + Vite, Arabic RTL UI, autosaved to `localStorage`, and exports a clean
Markdown answer file for turning into a project scope / SRS / MVP definition.

---

## التشغيل السريع

```bash
npm install
```

```bash
npm run dev
```

ثم افتح العنوان الذي يظهر في الطرفية (عادةً `http://localhost:5173`).

### الأوامر المتاحة

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | تشغيل خادم التطوير مع إعادة التحميل الفوري |

من القرص (تم ضبط `base: './'` في `vite.config.ts` لهذا الغرض).

## مصدر المحتوى

الملف `islamic_app_requirements_questionnaire_ar.md` هو **المصدر الوحيد للحقيقة** لمحتوى
الاستبيان. تمت ترجمته حرفيًا إلى `src/data/survey.ts`:

- **٧ أقسام** — بعناوينها وترتيبها الأصلي.
- **٣٥ سؤالًا** — بنصوصها وأرقامها الأصلية.
- **٢٧٥ خيارًا** — بنفس الصياغة وبنفس الترتيب.

الملاحظات الموجّهة لفريق التطوير في نهاية الملف المصدر لم تُعرض على المستخدم، بل نُفّذت
كسلوك في التطبيق (الأسئلة الشرطية، والحد الأقصى ٧ خيارات في السؤال ٣٢).

### تعديل الاستبيان

كل شيء يُرسم من إعدادات `src/data/survey.ts` — لا يوجد أي سؤال مكتوب يدويًا في الواجهة.
لإضافة سؤال، أضف كائنًا إلى `questions` داخل القسم المناسب:

```ts
{
  number: 36,
  type: 'multi',          // 'single' | 'multi' | 'shortText' | 'longText'
  text: 'نص السؤال؟',
  required: false,
  maxSelections: 5,        // اختياري — يفرض حدًا أقصى في الواجهة
  emphasis: true,          // اختياري — يمنح السؤال إطارًا بارزًا
  options: [
    'الخيار الأول.',
    'أخرى*',              // العلامة * تفتح حقل نص حر
  ],
}
```

> **تنبيه:** مُعرّفات الخيارات تُولَّد حسب الترتيب (`q12-o3`). إذا أعدت ترتيب الخيارات أو
> حذفت أحدها، ارفع `STORAGE_VERSION` في `src/hooks/useAutosave.ts` حتى تُهمل الإجابات
> المحفوظة سابقًا بدل أن تُربط بالخيار الخطأ.

### الأسئلة الشرطية

تُعرَّف قواعد الإظهار داخل بيانات السؤال نفسه:

```ts
conditionalVisibility: {
  questionId: 'q29',
  rule: 'notOneOf',                 // أو 'oneOf'
  optionIds: ['q29-o4'],
  hiddenNote: 'المحتوى سيكون ثابتًا داخل التطبيق دون لوحة تحكم.',
}
```

القواعد المُطبّقة حاليًا:

| السؤال | يظهر فقط عندما |
| --- | --- |
| ٢٦ — مزامنة البيانات | لا يكون الجواب على ٢٥ هو «لا، يجب أن يعمل التطبيق بالكامل بدون حساب» |
| ٣٠ — وظائف لوحة التحكم | لا يكون الجواب على ٢٩ هو «لا، سيكون المحتوى ثابتًا داخل التطبيق» |

**الإجابات المخفية لا تُحذف أبدًا.** إذا غيّر المستخدم رأيه وعاد، تعود إجابته كما كانت.
ويظهر السؤال المخفي في الملف المُصدَّر تحت وسم «لا ينطبق» مع سبب واضح.

## الأسئلة الإلزامية

معظم الأسئلة اختيارية ويمكن تخطّيها. الإلزامية أربعة فقط، وهي التي تحدد نطاق المشروع:

- **١** — الهدف الرئيسي من التطبيق
- **٢** — الفئة المستهدفة
- **٤** — التصور العام للتطبيق
- **٣٢** — أولويات النسخة الأولى (بحد أقصى ٧ خيارات)

لا يمنع التطبيق الإرسال بسبب أسئلة اختيارية غير مُجابة؛ تُعرض فقط في صفحة المراجعة وتُوسم
في الملف المُصدَّر بعبارة «لم تتم الإجابة».

---

## الحفظ التلقائي والخصوصية

- تُحفظ الإجابات في `localStorage` بعد ٦٠٠ مللي ثانية من آخر تعديل.
- عند إعادة فتح الصفحة تُستعاد الإجابات ويظهر إشعار صغير: «تم استعادة إجاباتك السابقة».
- زر «مسح جميع الإجابات» يعرض نافذة تأكيد قبل الحذف، ولا يترك أي أثر في المتصفح بعده.
- **لا يوجد خادم، ولا قاعدة بيانات، ولا أدوات تتبع أو تحليلات.** البيانات لا تغادر الجهاز
  إلا عبر الملف الذي ينزّله المستخدم بنفسه.

## الملف المُصدَّر

عند الضغط على «إنهاء الاستبيان وتحميل الملف» يُنشأ ملف باسم:

```
islamic-app-requirements-YYYY-MM-DD.md
```

ببنية منتظمة — عنوان لكل قسم، وعنوان فرعي لكل سؤال برقمه الأصلي، وكتلة `**الإجابة:**`
لكل سؤال — ويبدأ بملخص يشمل عدد الأقسام والأسئلة والمجاب عنها ونسبة الاكتمال. هذا الانتظام
مقصود ليُمكن تمرير الملف مباشرة إلى مطوّر أو إلى نموذج ذكاء اصطناعي لإنتاج نطاق المشروع،
والمتطلبات الوظيفية وغير الوظيفية، ووثيقة SRS، وتعريف الـ MVP.

## إمكانية الوصول

- كل الخيارات مبنية على `input` أصلية داخل `label` — تنقّل بالأسهم داخل مجموعة الاختيار
  الواحد، ومسافة للتبديل، ودعم كامل لقارئات الشاشة.
- حالات تركيز واضحة (`:focus-visible`) على كل عنصر تفاعلي، ورابط «تخطَّ إلى المحتوى».
- عند الانتقال بين الأقسام ينتقل التركيز إلى عنوان القسم، لا إلى بداية الصفحة فقط.
- لا تعتمد أي حالة على اللون وحده — «لم تتم الإجابة» مصحوبة بأيقونة ونص.
- مساحات لمس لا تقل عن ٤٨ بكسل على الجوال.
- احترام `prefers-reduced-motion`: تبقى تحولات الشفافية وتُلغى الحركة.
